# 자리(venue)별 기준

sepia의 `domains/*.md`를 한국어 업무 글에 맞게 줄였다. **같은 자리의 최근 사람 글 2~3편이 있으면 그게 기준이고, 이 파일은 표본이 없을 때만 쓴다.**

`genre`는 2단계 humanize-korean에 넘길 값이다(`essay | column | report | blog | abstract`).

| 자리 | genre | 사람 기준 | 먼저 볼 S 항목 |
|---|---|---|---|
| 사내 보고, 검토 문서 (Confluence, 1페이저) | report | 결론과 요청이 첫 단락에 있다. 근거는 수치와 출처로. 판단을 미루지 않는다 | S-10, S-3, S-4, S-5 |
| 메신저 답변 (슬랙 스레드) | report | 한두 문장. 답 먼저. 모르면 모른다고 하고 무엇을 확인할지 적는다 | S-10, S-2, S-1 |
| PR/이슈 답변, 리뷰 코멘트 | report | 답 먼저, `파일:줄`과 오류 원문 인용, 반대는 이유 하나와 함께. 반사적 칭찬 없음. 길이는 사안 크기에 비례 | S-10, S-4, S-2 |
| 장애 회고 (포스트모템) | report | 사람은 탓하지 않고 기전은 끝까지 판다. 시각, 막다른 길, 담당자 있는 후속 조치 | S-4, S-3, S-6 |
| 티켓, 작업 요청 | report | 제목이 결과. 검증 가능한 완료 조건. 반복하지 말고 링크 | S-4, S-2 |
| 기술 블로그, LinkedIn | blog | 문제에서 연다. 실제로 막혔던 길 하나, 분명한 의견 하나, 조건이 붙은 수치 | S-7, S-8, S-9, S-3 |
| 칼럼, 에세이 | column / essay | 도입과 본문의 결이 다르다. 요약으로 끝내지 않는다 | S-7, S-9, S-6 |

## 문서 모양별 가중

- **짧은 답변**(메신저, PR 답변, 티켓): 구체성(S-4)과 관련성(S-2)이 먼저다. 밀도와 어조는 짧은 글에서 덜 중요하다.
- **긴 글**(보고서, 회고, 블로그): 관련성, 밀도, 입장, 흐름(S-7, S-8)이 먼저다.

가중은 볼 순서일 뿐 면제가 아니다. 짧은 답이라도 채움말로 가득하면 S-1에 걸린다.
